شروع کار بار Docker Swarm

اگر با داکر کار کرده باشید، احتمالا تجربه بالا آوردن کانتینرها با دستور docker run یا فایل های docker-compose را دارید. این روش برای محیط های تستی و پروژه های تک سروره عالی است، اما وقتی بار ترافیک بالا می رود، سیستم نیاز به در دسترس پذیری بالا (High Availability) پیدا می کند یا یک سرور برای بار کاری شما کافی نیست، چه باید کرد؟

اینجا است که پای ارکستریشن (Container Orchestration) وسط می آید. در کنار غول پیچیده ای مثل کوبرنتیز (Kubernetes)، یک ابزار بومی، سبک و فوق العاده قدرتمند درست داخل خود داکر جا خوش کرده است: Docker Swarm.

در این پست وبلاگی، از صفر مطلق تا اجرای عملی یک کلاستر چند سروره و دیپلوی سرویس ها را با هم پیاده سازی می کنیم.

داکر سوارم (Docker Swarm) چیست و چرا باید از آن استفاده کنیم؟

داکر سوارم ابزار ارکستریشن رسمی و داخلی داکر است که چند سرور فیزیکی یا مجازی داکر را تبدیل به یک سرور واحد و منطقی (Cluster) می کند.

مزایای کلیدی Docker Swarm:

  1. بدون نیاز به نصب ابزار اضافه: اگر داکر روی سیستم شما نصب است، سوارم هم نصب است!
  2. منحنی یادگیری بسیار نرم: اگر با docker-compose کار کرده باشید، سوارم را در کمتر از چند ساعت یاد می گیرید.
  3. سبک و سریع: بر خلاف کوبرنتیز که رم و پردازنده زیادی را فقط صرف سیستم کنترلی خود می کند، سوارم بسیار سبک است و روی سرورهای اقتصادی هم روان کار می کند.
  4. سیستم لود بالانسینگ داخلی: درخواست ها به شکل خودکار بین کانتینرها پخش می شوند (Routing Mesh).
  5. سرویس دیسکاوری (Service Discovery): ارتباط بین سرویس ها با نام سرویس و DNS داخلی انجام می گیرد.

مفاهیم پایه ای که باید بدانید

قبل از دست به کد شدن، این چهار مفهوم را به خاطر بسپارید:

  • Node (نود): هر سروری که عضو کلاستر است. نودها دو دسته هستند:

    • Manager: وظیفه مدیریت کلاستر، زمان بندی کارها و نگهداری وضعیت را دارد (توصیه می شود در پروداکشن حداقل ۳ منیجر داشته باشید تا الگوریتم Raft فعال بماند).
    • Worker: فقط کانتینرها و بارهای کاری را اجرا می کند.

  • Service: تعریفی از کانتینری که می خواهید اجرا شود (مثلا: سه نسخه از Nginx روی پورت 80).

  • Task: هر نسخه تکی از یک کانتینر که توسط یک Service روی یک نود اجرا می شود.

  • Stack: مجموعه ای از چند سرویس مرتبط با هم (معادل مدرن تر و چند سروره فایل های compose).

سناریوی عملی: راه اندازی کلاستر 3 نوده

فرض کنیم 3 سرور لینوکسی (مثلا Ubuntu) با آی پی های زیر داریم:

  • سرور 1 (Manager): 192.168.1.10
  • سرور 2 (Worker 1): 192.168.1.11
  • سرور 3 (Worker 2): 192.168.1.12

نکته امنیتی شبکه: مطمئن شوید پورت های زیر بین این سه سرور باز هستند:

  • پورت 2377/tcp برای ارتباطات مدیریتی کلاستر
  • پورت 7946/tcp و 7946/udp برای ارتباط بین نودها
  • پورت 4789/udp برای شبکه همپوشان (Overlay Network)

گام اول: راه اندازی نود Manager

وارد سرور اول (192.168.1.10) شوید و دستور زیر را اجرا کنید:

docker swarm init --advertise-addr 192.168.1.10

داکر در پاسخ پیامی شبیه به این به شما می دهد:

Swarm initialized: current node (xyz...) is now a manager.

To add a worker to this swarm, run the following command:

    docker swarm join --token SWMTKN-1-49nj1... 192.168.1.10:2377

این توکن دقیقا همان کلیدی است که برای اتصال ورکرها نیاز دارید.

گام دوم: اضافه کردن Worker ها به کلاستر

وارد سرور دوم و سوم شوید و دستوری که داکر در مرحله قبل تولید کرد را داخل آنها وارد کنید:

docker swarm join --token SWMTKN-1-49nj1... 192.168.1.10:2377

برای چک کردن وضعیت، دوباره به سرور Manager برگردید و دستور زیر را بزنید:

docker node ls

خروجی باید هر 3 سرور را با وضعیت Ready و نقش های مشخص نمایش دهد:

ID          HOSTNAME    STATUS   AVAILABILITY   MANAGER STATUS   ENGINE VERSION
abc *       manager1    Ready    Active         Leader           24.0.5
def         worker1     Ready    Active                          24.0.5
ghi         worker2     Ready    Active                          24.0.5

تبریک! کلاستر شما بالا آمد و آماده کار است.

گام سوم: ساخت و اجرای یک سرویس ساده

بیایید یک سرویس Nginx ساده با 3 کپی (Replica) بسازیم:

docker service create --name my-web --replicas 3 -p 8080:80 nginx:alpine

این دستور چه کار کرد؟

  1. یک سرویس با نام my-web ساخت.
  2. داکر به شکل خودکار 3 کانتینر از روی این ایمیج ساخت و روی نودهای کلاستر پخش کرد.
  3. پورت 8080 سرور را به پورت 80 کانتینرها متصل کرد.

حالا وضعیت سرویس را ببینید:

docker service ls
docker service ps my-web

دستور service ps دقیقا نشان می دهد هر نسخه از کانتینر روی کدام سرور در حال اجرا است. جالب ترین نکته سیستم Routing Mesh این است: شما آی پی هر کدام از 3 سرور را در مرورگر با پورت 8080 باز کنید، وب سرور باز می شود، حتی اگر روی آن سرور خاص هیچ کانتینری از Nginx اجرا نشده باشد! ترافیک خودش به سمت سرور درست روت می شود.

گام چهارم: مقیاس پذیری لحظه ای (Scaling)

اگر ترافیک بالا رفت و 3 نسخه کم بود، چه کنیم؟ خیلی راحت:

docker service scale my-web=6

در عرض چند ثانیه 3 کانتینر جدید روی سرورها ایجاد شده و به چرخه پردازش درخواست ها اضافه می شوند.

گام پنجم: بروزرسانی بدون قطعی (Rolling Update)

اگر بخواهیم ایمیج یا نسخه سرویس را آپدیت کنیم بدون اینکه سایت حتی 1 ثانیه قطع شود:

docker service update --image nginx:latest --update-parallelism 1 --update-delay 10s my-web

این دستور:

  • کانتینرها را تک به تک (–update-parallelism 1) آپدیت می کند.
  • بین هر آپدیت 10 ثانیه صبر می کند تا کانتینر قبلی سالم بالا بیاید (–update-delay 10s).
  • اگر خطایی رخ دهد، می توان با دستور docker service rollback my-web همه چیز را فورا به حالت قبل برگرداند.

گام حرفه ای: مدیریت چند سرویس با Docker Stack

در پروژه های واقعی به ندرت با دستور تک خطی docker service create کار می کنیم. در عوض از فرمت محبوب docker-compose.yml تحت عنوان Stack استفاده می شود.

بیایید یک فایل به نام docker-stack.yml بسازیم:

version: '3.8'

services:
  web:
    image: nginx:alpine
    ports:
      - "80:80"
    deploy:
      replicas: 3
      restart_policy:
        condition: on-failure
      resources:
        limits:
          cpus: '0.50'
          memory: 256M
    networks:
      - app-net

  api:
    image: node:20-alpine
    command: node -e "const http = require('http'); http.createServer((req, res) => res.end('Hello from Swarm API')).listen(3000);"
    deploy:
      replicas: 2
    networks:
      - app-net

networks:
  app-net:
    driver: overlay

اجرای Stack:

کافی است در سرور Manager دستور زیر را بزنید:

docker stack deploy -c docker-stack.yml myapp

داکر به طور خودکار شبکه اورلی (Overlay) را می سازد، سرویس ها را استقرار می دهد و ارتباط شبکه ای امن و ایزوله بین کانتینرها برقرار می کند.

برای بررسی وضعیت استک:

docker stack ls
docker stack services myapp

برای حذف کل استک:

docker stack rm myapp

مدیریت لاگ ها و مانیتورینگ نودها

برای دیدن لاگ های یک سرویس بدون نیاز به دانستن اینکه کانتینر کجاست:

docker service logs -f myapp_web

این دستور به صورت یکپارچه لاگ تمام کانتینرهای سرویس را در ترمینال شما استریم می کند.

اگر نیاز داشتید یک سرور را برای تعمیرات یا ریبوت از مدار خارج کنید تا کانتینرهایش روی سرورهای دیگر منتقل شوند:

docker node update --availability drain worker1

و بعد از اتمام کار و بازگرداندن سرور:

docker node update --availability active worker1

جمع بندی: چه زمانی سوارم و چه زمانی کوبرنتیز؟

  • سوارم را انتخاب کنید اگر: تیم زیرساخت بزرگی ندارید، نمی خواهید درگیر پیکربندی های سرسام آور و ابزارهای متعدد کوبرنتیز شوید، مصرف بهینه منابع سرور برایتان اولویت است و سادگی و پایداری سریع می خواهید.
  • کوبرنتیز را انتخاب کنید اگر: صدها مایکروسرویس با معماری های فوق پیچیده، نیاز به ابزارهای پیشرفته اتواسکیلینگ کلاستر، و نیاز به قابلیت های بسیار خاص در لایه ذخیره سازی و شبکه دارید.

داکر سوارم ابزاری است که در دنیای واقعی کار راه انداز، بسیار پایدار و به شدت خوش دست است و برای 90 درصد شرکت ها و پروژه ها پاسخی دقیق و کافی است.
