نقشه راه یادگیری هک و امنیت پیام رسان ها

مقدمه

امنیت پیام رسان ها یکی از جذاب ترین حوزه های Cyber Security است؛ چون یک پیام رسان معمولا ترکیبی از چندین تکنولوژی مختلف است: Mobile Application، Backend، API، Database، Authentication، Cryptography، Network Protocol و زیرساخت Server.

بنابراین برای اینکه بتوانیم امنیت یک پیام رسان را به شکل حرفه ای بررسی کنیم، صرفا یادگیری یک ابزار مثل Burp Suite یا Wireshark کافی نیست. باید ابتدا یک پایه فنی قوی ایجاد کنیم و سپس به صورت مرحله ای وارد حوزه های مختلف امنیت شویم.

توجه داشته باشید که آشنایی با هک پیام رسان ها و ایمن سازی موضوعی است که همه افراد جامعه جهت حفظ امنیت خود باید تا حدی از آن آگاه باشند.

هدف این نقشه راه، یادگیری Ethical Hacking و Security Research با تمرکز روی پیام رسان ها و محیط های آزمایشگاهی و دارای مجوز است.

مرحله سوم: Web Security

بخش بزرگی از یک پیام رسان به Backend و API وابسته است.

بنابراین باید Web Security را به خوبی یاد بگیریم.

مباحث مهم:

  • HTTP
  • Cookies
  • Sessions
  • Authentication
  • Authorization
  • JWT
  • OAuth
  • REST API
  • GraphQL
  • WebSocket
  • CORS
  • CSRF
  • XSS
  • SQL Injection
  • NoSQL Injection
  • SSRF
  • IDOR
  • Path Traversal
  • File Upload Security
  • Rate Limiting
  • Business Logic Vulnerabilities

یکی از مهم ترین موضوعات در این مرحله، تفاوت بین Authentication و Authorization است.

مثلا اینکه سیستم تشخیص دهد شما چه کسی هستید، Authentication است؛ اما اینکه آیا اجازه مشاهده یک Resource خاص را دارید یا نه، Authorization است.

پیام رسان ها معمولا وابستگی بسیار زیادی به API دارند.

در این مرحله باید یاد بگیریم API را از دیدگاه Security بررسی کنیم.

موضوعات مهم

  • Access Control

  • API Rate Limiting
  • Input Validation
  • Object Level Authorization

  • Business Logic

در این مرحله وارد بخش جذاب تر Security Research می شویم.

باید بتوانیم یک Application یا Binary را بدون داشتن Source Code بررسی کنیم.

مباحث:

  • PE
  • ARM

  • Dynamic Analysis
  • Debugging

مرحله هفتم: Network Security و Protocol Analysis

پیام رسان ها فقط HTTP API نیستند.

ممکن است از:

  • WebSocket
  • TCP
  • UDP
  • HTTP/2
  • QUIC
  • Custom Binary Protocol

استفاده کنند.

در این مرحله باید بتوانیم Traffic را Capture و تحلیل کنیم.

ابزارها

  • Wireshark
  • mitmproxy
  • Burp Suite
  • tcpdump

همچنین باید مفهوم TLS را به صورت عمیق تری یاد بگیریم.

مرحله هشتم: Cryptography

این مرحله بسیار مهم است.

پیام رسان های امن معمولا از Cryptography برای حفاظت از پیام ها استفاده می کنند.

موضوعات:

  • Hash
  • HMAC
  • Randomness
  • Symmetric Encryption
  • Asymmetric Encryption
  • RSA
  • ECC
  • AES
  • ChaCha20
  • Digital Signature
  • Key Exchange
  • Key Derivation
  • Forward Secrecy

اما صرفا دانستن الگوریتم ها کافی نیست.

باید بفهمیم چگونه یک سیستم Cryptographic Protocol طراحی می شود و چگونه ممکن است در پیاده سازی اشتباه شود.

برای مثال:

  • Key Management
  • Nonce Reuse
  • Weak Randomness
  • Improper Authentication
  • Key Leakage
  • Replay Protection

مرحله نهم: امنیت Storage

نکته مهم

هدف این مسیر، یادگیری هک کردن افراد یا ورود غیرمجاز به حساب کاربران نیست.

Security Research زمانی ارزشمند است که روی سیستم هایی انجام شود که مالک آنها هستیم، محیط آزمایشگاهی داریم یا اجازه صریح برای تست آنها دریافت کرده ایم.

برای مثال، به جای تلاش برای نفوذ به یک پیام رسان واقعی، می توان یک پیام رسان آزمایشگاهی ساخت، Traffic آن را بررسی کرد، APK آن را تحلیل کرد، API های آن را تست کرد و Vulnerability های آن را پیدا و Patch کرد.

این روش علاوه بر اینکه از نظر قانونی و اخلاقی درست است، از نظر آموزشی نیز بسیار عمیق تر است؛ چون می توانیم تمام اجزای سیستم را کنترل کنیم و نتیجه آزمایش ها را دقیقا بررسی کنیم.
